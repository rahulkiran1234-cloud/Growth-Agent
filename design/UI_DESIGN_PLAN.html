1 · Diagnosis

Why it feels like a form, and what we change

What the product feels like today

  • Linear, one-shot flow. Create project → upload → click Run → read a long page. There is nothing to come back to or explore.
  • Tables and paragraphs, almost no charts. A trend (revenue slipping 13.8% since April) is a sentence, not a picture you can see in one second.
  • The report is a document, not a workspace. You cannot filter by product or period, or click a number to see where it came from.
  • Value only appears after a 4-minute agent run. Yet the uploaded data alone could already draw most of the useful charts.
  • The plan is a checklist form. No sense of impact, effort, or time.

Design principles for the new UI

  1. Answer first, detail on demand. Each screen opens with its headline finding in one line, then the chart that proves it.
  2. Chart before table. Every metric gets a trend, a comparison, or a breakdown. Tables sit behind “View data”.
  3. Instant value. Charts that need only your data appear seconds after upload, before the AI finishes. The agent adds the “why” and “what to do” on top.
  4. Every number is traceable. Click it to open an evidence drawer with the SQL result or the quoted competitor passage. That is our trust advantage.
  5. Honest about uncertainty. Correlations are labelled as correlations; estimates show ranges, with a confidence badge.
  6. One screen, one question. “How am I doing?”, “What did price do?”, “What do customers say?”, “How do I compare?”, “What now?”

5 · Technical approach & delivery

How we would build it

Keeps the current Next.js 16 / Tailwind / Postgres stack. No change to the agent.

Approach

  • Stack additions: shadcn/ui (Radix) for components, Recharts wrapped in our own <Chart> components so the library can be swapped, TanStack Table for sortable tables, lucide icons, dnd-kit for the week board. U0 starts with a one-day compatibility check against React 19 / Next 16.
  • Instant dashboards: a new /api/projects/[id]/insights returns chart-ready series straight from SQL, so charts render right after upload, before the analysis finishes.
  • Caching: cache insights per project and data version, invalidated on re-upload (use Next 16 Cache Components; read the bundled docs first, per AGENTS.md).
  • Evidence drawer: one shared component that resolves sql_kpis:* and chunk:N references already stored by the agent.
  • PDF: keep print-to-PDF; add a print layout that reuses the same chart components (SVG prints crisply).
  • No agent changes except a small step-4 field so each problem links to the chart it relates to.
  • Testing: unit tests for new derived metrics; screenshot checks of each screen at desktop and phone width; extend the existing E2E script.
